# Top Apps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a per-network, per-app data usage table ("Top apps") with real app icons, which users opt into, on macOS (verified), Windows and Linux (experimental).

**Architecture:**
- **Where the numbers come from.** Each sample produces per-process cumulative byte counters:
  - **macOS:** `nettop`, run in-process.
  - **Windows and Linux:** a privileged helper service writes them atomically to a snapshot JSON file.
- **Turning counters into app usage.** `overlook-core` groups processes into apps and turns the counters into deltas, using the same gap and reset rules as `processor.rs`. It stores them in hourly `app_usage` buckets keyed by (network, hour, app), plus an `app_coverage` table. The writes happen in the existing sample transaction.
- **The table.** The React table computes the System remainder and the shares from the app totals and the network total over hours with per-app coverage.

**Tech Stack:** Rust (rusqlite, serde_json, base64; helper: netlink-packet-sock-diag/netlink-sys on Linux, ferrisetw/windows-service/windows on Windows), Tauri 2, React 19 + TypeScript, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-26-top-apps-design.md`

## Global Constraints

- Per-app tracking is **off by default**. Nothing elevates or spawns a helper until the user confirms the disclosure dialog.
- Existing per-network collection must behave identically when per-app is off, denied or failing.
- No UI or chart libraries. Generic icons come from Hugeicons only (`CubeIcon` for an unknown app, `ComputerIcon` for System).
- Images are `data:` URLs (CSP already allows `img-src 'self' data:`).
- `overlook-core` must still pass `cargo check -p overlook-core --no-default-features --target x86_64-pc-windows-msvc` (and the Linux target).
- Windows and Linux per-app tracking is labelled **Experimental** in the dialog and in Settings.
- Copy is fixed by the spec:
  - Subtitle: `"{total} across {n} apps · {range title}"`.
  - Partial range: `"Per-app data since {date}"`.
  - Empty: `"No app traffic recorded in this range yet."`.
  - Off: button `"Turn on per-app tracking"`.
- Only the top 10 rows show, then a `"+ N more"` row that expands in place. Rows are not clickable.
- Per-app history follows the existing retention setting and **Delete all data**.

## Review Focus

1. **PID reused by a different executable between samples.** It must count as a new process, never as a negative or huge delta. Test: `tracker_pid_reuse_is_new_process` (Task 1).
2. **Process names containing dots or commas in `nettop` output** (`Code Helper (Plugin).812`, `Foo, Inc.44`). The PID must still parse. Test: `nettop_names_with_dots_and_commas` (Task 1).
3. **Apps summing to more than the network total.** System is clamped to 0 and shares still total 100%. Test: `clamps system and rescales shares when apps exceed total` (Task 7).
4. **Per-app is on but the source fails** (missing or stale snapshot, `nettop` error). Network usage must still be written, and the status must carry the error. Test: `per_app_failure_keeps_network_collection` (Task 3).
5. **A range that starts before tracking began, in the All-networks view.** Only covered hours count toward the denominator. Test: `covered_totals_only_count_app_covered_hours` (Task 2).

### Task 4: The per-app privileged helper (Linux and Windows)

**Files:**
- Create: `crates/overlook-helper/Cargo.toml`, `crates/overlook-helper/src/main.rs`, `src/linux.rs`, `src/windows.rs`, `src/acc.rs`
- Modify: `Cargo.toml` (workspace member)

**Interfaces:**
- Produces:
  - A binary `overlook-helper` with these modes:
    - `run --owner <uid|username>`: the loop.
    - On Windows, `service`: the SCM entry, which uses `windows-service`.
  - Every 5 s it writes `{ "session": "<start unix secs>", "at": <now>, "procs": [{pid, path, rx, tx}] }` to `SNAPSHOT_PATH`. It writes `*.tmp` first, then renames. The snapshot keeps the same field names as `ProcSample`/`Snapshot` in Task 1; duplicate the tiny struct rather than depending on core.
  - Linux sets the file mode to `0640` with the owner's gid. Windows applies `icacls` granting `SYSTEM:F` and `<owner>:R` with inheritance removed.
  - On macOS, `main` prints `unsupported` and exits with code 1.
  - `acc.rs` (pure, tested on any host): `pub struct Acc` with `pub fn observe(&mut self, socket: u64, pid: u32, rx: u64, tx: u64)`, `pub fn end_round(&mut self)` and `pub fn totals(&self) -> HashMap<u32, (u64, u64)>`.
    - A socket that disappears between rounds keeps its last bytes in its pid's closed sum.
    - Per-pid totals never decrease while the pid lives.
    - Windows ETW feeds per-event sizes with `observe(event_seq, pid, size_rx, size_tx)`, which is equivalent to adding to the closed sum straight away.
  - **Linux** (`linux.rs`):
    - Uses netlink `sock_diag` (`netlink-packet-sock-diag`, `netlink-sys`) to dump TCP v4 and v6 sockets with `INET_DIAG_INFO`. It takes `tcpi_bytes_received` as rx and `tcpi_bytes_acked` as tx, skips loopback destinations, and maps socket inodes to pids through `/proc/*/fd` links `socket:[N]`.
    - The path comes from `/proc/<pid>/exe`.
    - Add the comment `// ponytail: TCP only, UDP/QUIC falls into System; upgrade to eBPF cgroup_skb for full coverage`.
  - **Windows** (`windows.rs`):
    - Runs a `ferrisetw` kernel trace for network TCP/IP and UDP send and receive events. Each event provides the pid and size. It skips loopback addresses.
    - The path comes from `QueryFullProcessImageNameW`.
